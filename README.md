# 校车早班班次调配台

早班校车按车牌排队。当**司机请假**或**道路积水**时，系统锁定原车，按硬性条件匹配替换组合；
新车**接管确认后原车才释放**；没有合适组合时线路进入候车区，并写清缺的是座位还是照管员。
每笔调整都能追溯到原车、新车和触发条件；数据持久化在浏览器 localStorage，重开页面仍能核对当天安排。

## 业务规则

- **线路登记**：学生数、途经片区、发车时间、到校时限、按车牌排队的默认车辆。
- **车辆登记**：核定座位、是否配随车照管员、服务/停靠片区、准驾要求（A1/A3/B1，A1 可准驾低等级车辆）。
- **司机登记**：准驾证、当日班次窗口、当日工时上限、绑定车辆。
- **替换组合必须同时满足**：
  1. 座位 ≥ 线路学生数；
  2. 覆盖线路所有未积水的途经片区（积水站点当日取消接人，停靠片区积水的车辆不能出场，全线积水则全线停驶）；
  3. 配备随车照管员；
  4. 司机准驾证等级 ≥ 车辆要求；
  5. 趟次窗（发车前 15 分钟点检 → 到校时限）落在司机班次内，且累计工时不超上限；
  6. 车辆、司机在该时段无其他趟次冲突；
  7. 原车与原司机在接管确认前保持锁定，不会被再次选用。
- **状态机**：
  - 派位：`planned → held（原车锁定）→ released（接管确认后释放）`；替换派位：`proposed → confirmed`。
  - 调整单：`proposed（方案待确认）/ waiting（候车区）→ confirmed / cancelled`。
- 候选组合按"车牌排队"顺序、座位浪费最少、优先备车绑定司机排序，可人工改选，改选同样过全部硬校验。

## 可追溯性

- 每张调整单记录：触发条件（请假司机/积水片区+原因）、原车原司机、新车新司机、缺口明细、时间戳。
- 当天事件流水（append-only）：排班、提出方案、进入候车区、改选、接管确认、撤销。
- 全部状态序列化到 localStorage（键 `school-bus-dispatch-v1`），重开即恢复。

## 启动

```bash
npm install
npm run dev      # 本地开发
npm run build    # 类型检查 + 生产构建
```

## 引擎场景验证

纯函数式调度引擎位于 `src/lib/engine.ts`，端到端场景脚本 `src/test-engine.ts`（不参与前端构建）：

```bash
node_modules/.bin/esbuild src/test-engine.ts --bundle --platform=node --format=esm --outfile=/tmp/t.mjs && node /tmp/t.mjs
```

覆盖：成功接管且确认后才释放原车、积水停驶、缺座位、座位够但缺照管员、准驾高低准驾、
班次工时/时间冲突拦截、人工改选校验、流水与序列化重开核对。

## 技术栈

Vue 3 + Vite + TypeScript + Pinia，无 UI 框架依赖的原生控件与样式。
