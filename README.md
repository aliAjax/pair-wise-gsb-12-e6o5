# 校车早班调配台

早班校车按车牌排队。司机请假或道路积水时，在满足座位、片区、涉水、照管员、准驾证和工时的前提下重排车辆与司机；**原车在接管确认后才释放**；没有合适组合的班次留在候车区，写清缺的座位、照管员、司机或时限。每笔调整记录原车、新车（含司机）与触发条件，重开页面仍可核对当天安排。

## 启动

```bash
npm install
npm run dev        # 本地开发
npm run selftest   # 引擎与状态机自测（31 项）
npm run build      # 类型检查 + 构建
```

数据保存在浏览器 localStorage：登记数据一份，当天调配按日期各存一份；支持导出/导入 JSON 备份与交接核对。

## 业务规则

**登记（登记管理页可增删改）**

- 线路：登记学生数、途经片区、到校时限、全程分钟、是否需照管员、原配车辆/司机
- 车辆：座位数、在车照管员、可通行片区、所需准驾证（A1/A3）、是否可涉水
- 司机：准驾证（A1 可覆盖 A3）、当日班次（早班）、当日请假、已排工时

**替换车辆必须同时满足**

1. 座位 ≥ 线路学生数（候车区写明缺几个座）
2. 覆盖线路全部途经片区；积水触发时涉及积水片区的车必须可涉水
3. 线路要求时配备照管员（候车区写明缺照管员）
4. 司机准驾证覆盖本车、有当日早班、未请假、未被其他班次占用
5. 接此班后当日工时不超过 4 小时
6. 现在出发 + 全程分钟能赶在到校时限前；不可达则直接留候车区

**两阶段接管**

1. 触发（司机请假 / 道路积水勾选片区）→ 系统匹配候选组合，班次为"待接管"，**原车与原司机仍占用**，不会被再次分派
2. 选定组合 → 点"确认接管"，原车才释放，执行车/司机切换；也可撤销让原车继续
3. 无候选 → 进候车区，逐条列出缺项；登记补充后可"重新匹配"

**追溯与核对**

- 台账流水：时间、班次、动作（触发/选定/确认接管/撤销/重新匹配/留候）、触发条件、原车原司机、新车新司机、说明
- 台账页"当天最终安排"按车牌给出排队、执行车辆/司机、状态；切换日期可看其他日数据
- 接管过的班次再次触发时，以当前执行组合作为"原车"快照，链条不断

## 代码结构

```
src/
  types.ts              领域模型
  data/seed.ts          示例登记数据（4 条线 / 5 辆车 / 6 名司机）
  engine/dispatch.ts    纯函数匹配引擎（占用计算、候选与缺额）
  store/bus.ts          Pinia 状态机：触发→候选→确认→候车区、台账、持久化
  components/           当班看板 / 候车区 / 登记管理 / 调配台账
tests/selftest.ts       规则、两阶段流程、缺额、重开持久化自测
```
